# K리그 캐릭터 일정 앱 (Flutter)

사용자가 K리그1/K리그2 중 리그를 선택하고, 내 팀(캐릭터)을 고르면 해당 팀의 경기 일정과 결과를 확인할 수 있는 예제 앱입니다.

## 포함 기능

- K리그1 / K리그2 리그 선택
- (샘플 기준) K리그1 12팀, K리그2 17팀 전체 선택 목록 제공
- 리그별 팀(캐릭터) 선택
- 선택한 팀의 경기 일정/결과 확인
- 다른 팀들의 경기 결과 확인
- 마스코트 기반 주간 캘린더 + VS 결과 하이라이트 위젯 제공
- 비동기 데이터 로딩 시뮬레이션 (`Future`)

## 실행

```bash
flutter pub get
flutter run
```

## 실제 서비스 확장 포인트

- `_fetchResults()`를 K리그 공식 데이터 API 또는 자체 백엔드 연동으로 교체
- 팀 캐릭터 이미지를 `assets/`로 관리하고 카드 UI 강화
- 라운드별 필터, 날짜 필터, 푸시 알림(경기 시작 전)

## K리그 공식 공개 API가 없을 때 데이터 연동 방법

공식 공개 API가 없다면, 앱에서 외부 사이트를 직접 호출하기보다 **중간 백엔드(BFF)** 를 두는 방식을 권장합니다.

1. **데이터 소스 확보**
   - K리그 홈페이지/구단 홈페이지/포털 스포츠 페이지처럼 공개된 경기 일정을 제공하는 소스를 선정
   - 가능한 경우 제휴 데이터 제공사(Sportradar 등) 사용 검토

2. **수집 레이어 구성**
   - 서버에서 크롤러 또는 파서(스케줄러 기반)를 돌려 경기 일정/결과를 주기적으로 수집
   - 소스별 HTML 구조 변경에 대비해 파서를 분리하고 모니터링 알림 구성

3. **표준 스키마로 정규화**
   - 홈/원정 팀명 매핑 테이블 운영 (예: FC서울 = 서울)
   - 경기 상태(예정/진행중/종료), 라운드, 킥오프 시간, 스코어를 단일 포맷으로 저장

4. **앱 전용 API 제공**
   - `/leagues`, `/teams`, `/matches?teamId=...` 형태의 REST API 또는 GraphQL 제공
   - 앱은 이 API만 호출하고, 소스 변경 대응은 서버에서만 처리

5. **운영 안정성**
   - 캐시(예: 1~5분), 재시도, 레이트리밋, 장애 시 마지막 정상 데이터 fallback 적용
   - 변경 이력/수집 실패 로그를 남겨 데이터 품질 관리

### 최소 권장 아키텍처

- **Collector Worker**: 외부 페이지 수집/파싱
- **DB**: 정규화된 경기/팀/리그 데이터 저장
- **API Server**: Flutter 앱이 호출하는 단일 엔드포인트 제공
- **Admin/Monitoring**: 팀명 매핑, 실패 알림, 데이터 검수
